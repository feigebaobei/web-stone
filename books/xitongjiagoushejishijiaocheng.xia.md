## 第 12 章 信息系统架构设计理论与实践

信息系统架构 Information System Architecture ISA 是一种体系结构

### 信息系统架构基本概念及发展

对于大规模的复杂系统来说，总体的系统结构设计比计算算法和数据结构更重要。
信息系统的架构本质上存在 2 个层次：

- 概念层次
- 物理层次
  信息系统架构是关于软件系统的结构、行为和属性的高级抽象。
  企业架构框架是 TOGAF The Open Group Archietecture Framework, open group 架构框架
  几乎所有领域都能够和信息技术相结合 构成企业信息化项目。
  包括：
- 信息系统架构描述语言
- 信息系统架构的描述与表示
- 信息系统架构的分析与验证
- 基于架构的软件维护与演化
- 信息系统架构的可靠性
  关于其定义中的说明：
- 架构是系统的抽象
- 架构由多个结构组成
- 任何软件都存在架构
- 元素及其行为的集合构成架构的内容
- 架构具有“基础”性。
  - 通常涉及解决各类关键重复问题的能用方案
  - 系统设计中影响深远的各项重要决策
- 架构隐含有“决策”
  - 架构设计师根据功能与非功能需求进行设计与决策的结果
    影响架构的因素：
- 软件系统的干系人对其有不同的要求
- 开发组织有不同的人员知识结构
- 架构设计师的素质与经验
- 当前的技术环境
  这些因素也会影响架构。

### 信息系统架构

信息系统设计的一个核心问题是能否使用重复的信息系统架构模式，即能否达到架构级别的软件重用。即能否在不同的软件系统中使用同一架构。
信息系统架构风格是描述某一特定应用领域中系统组织方式的惯用模式。
约束指出系统是如何将构件和连接件组合起来的。
根据特定项目的具体特点选择或设计特写的架构风格：

- 数据流风格：批处理序列，管道、过滤器
- 调用、返回风格：主程序、子程序，面向对象风格，层次结构
- 独立构件风格：进程通信，事件系统
- 虚拟机风格：解释器，基于规则的系统
- 仓库风格：数据库系统，超文本系统，黑板系统
  信息系统架构分类：

1. 信息系统物理结构
   - 在空间上的拓扑关系
   - 集中式结构
     - 物理资源有空间上集中配置
     - 优点
       - 资源集中
       - 便于管理
       - 资源利用率较高
     - 缺点
       - 维护、管理比较困难
       - 不利于用户发挥在信息系统建设过程中的积极性与主动性
       - 过于集中会造成系统的脆弱
   - 分布式结构
     - 通过计算机网络把不同地点的计算机硬件、软件、数据等资源联系在一起，实现不同地点的资源共享。
     - 分布式结构已经成为信息系统的主流模式。
     - 优点
       - 按需配置资源
       - 安全性好。一个结点出现故障不会导致整个系统停止运作
     - 缺点
       - 系统管理的标准不统一。
     - 分类
       - 一般分布式
       - 客户机、服务器
2. 信息系统的逻辑结构
   - 信息系统的逻辑结构是其功能综合体和概念性框架
   - 一个完整的信息系统支持组织的各种功能子系统
   - 将信息系统按职能划分成一个个职能子系统，然后逐个研制和开发。
   - 强调各子系统之间的协调一致性和整体性。
   - 横向综合
   - 纵向综合
   - 纵横综合

#### 企业信息系统的总体框架

信息系统架构 Information System Architecture ISA

```
    战略管理                      战略系统
    -----------------------------------------------------
    战术管理                    业务系统    应用系统
    -----------------------------------------------------
    运行管理                     信息基础设施
```

##### 战备系统

企业中与战略制定、高层决策有关的管理活动和计算机辅助系统。
组成：

- 以计算机为基础的高层决策支持系统。
- 企业的战略规划体系。
  意义
- 信息系统对企业高层管理者的决策支持能力
- 企业战略规划对信息系统建设的影响和要求

##### 业务系统

完成一定业务功能的各部分组成的系统。
作用：

- 对企业现有业务系统、业务过程和业务活动进行建模。
- 在企业战略的指导下，采用业务流程重组的原理和方法进行业务过程优化重组。
- 并对重组后的业务领域、业务过程和业务活动进行建模，从而确定出相对稳定的数据
- 以此相对稳定的数据为基础，进行企业应用系统的开发和信息基础设施的建设

##### 应用系统

即应用软件系统。

##### 企业信息基础设施 Enterprises Information Infrastructure EII

可分成 3 部分：

- 技术基础设施由计算机、网络、系统软件、支持性软件、数据交换协议等组成。
- 信息资源设施由数据与信息本身、数据交换的形式与标准、信息处理方法等组成。
- 管理基础设施指企业中信息系统部门的组织结构、信息资源设施管理人员的分工、企业信息基础设施的管理方法与规章制度等。

### 信息系统架构设计方法

#### ADM 架构开发方法

The Open Group Architecture Framework TOGAF 是一种开放式企业架构框架标准。由国际标准权威组织 The Open Group 制定。
它是基于一个迭代(Iterative)的过程模型，支持最佳实践和一套可重用的现有架构资产。
功能：

- 确保从关键利益相关方到团队成员的所有用户都使用相同的语言。
- 避免被“锁定”到企业架构的专有解决方案。
- 节省时间和金钱，更有效地利用资源。、
- 实现可观的投资回报。
  TOGRF 的 6 个组件：
- 架构开发方法 Architecture Development Method ADM. 即一种开发企业架构的分步方法。
- ADM 指南和技术 可用于应用 ADM 的指南和技术
- 架构内容构架
- 企业连续体和工具
- 参考模型：技术参考模型、集成信息基础设施参考模型
- 架构能力框架
  其框架的核心思想：
- 模块化架构
- 内容框架
- 扩展指南
- 架构风格

##### ADM 架构开发方法

定义开发企业架构所需要执行各个步骤以及它们之间的关系。

###### ADM 的架构开发阶段

由一组按照架构领域的架构开发顺序而排列成一个环的多阶段所构成。
十个阶段是反复迭代的过程。
每个阶段都需要根据原始业务需求对设计结构进行确认。
3 个级别的迭代概念：

- 基于 ADM 整体的迭代
- 多个开发阶段间的迭代
- 在一个阶段内部的迭代。

```
                        预备阶段
                           ^
                           |
                           V
    H. 架构变更治理 <----> A. 架构愿景 <----> B. 业务架构
          ^ \              ^              / ^
          |   \            |            /   |
          |     \          |          /     |
          |       \        |        /       |
          |         \      |      /         |
          |           \    |    /           |
          V             \  V  /             V
    G. 实施治理 <----> 需求管理 <----> C. 信息系统架构
          ^             /  ^  \             ^
          |           /    |    \           |
          |         /      |      \         |
          |       /        |        \       |
          |     /          |          \     |
          |   /            |            \   |
          V /              V              \ V
    F. 迁移规划 <----> E. 机会及解决方案 <----> D. 技术架构
```

预备阶段

- A. 架构愿景 将启动一次架构开发过程的迭代，设置迭代工作的范围、约束、期望，创建架构愿景、验证业务上下文，创建架构工作说明书并取得大家的一致认可。
- B. 业务架构 将开发一个支持架构愿景的业务架构。架构愿景中概括的基线和目标业务架构将在此被细化，从而使它们可以作为技术分析的有效输入。
- C. 信息系统架 确定主要的信息类型和处理这些信息的应用系统。在本阶段有 2 个主要的步骤，数据架构设计和应用架构设计。二者可以依次开发，也可以并行开发。
- D. 技术架构 完成对系统基础服务设施的设计，定义了架构解决方案的物理实现。
- E. 机会及解决方案 确定目标架构交付物
- F. 迁移规划 制订一个详细的实现和迁移计划，完成从基线架构向目标架构的转变。
- G. 实施治理 实施项目的架构结束，提供项目构建的架构监督，产生一个架构契约。
- H. 架构变更治理 确保以一种可控制的方式对架构的改变进行管理。
- 需求管理 是一个动态的过程，完成对企业需求的识别、存储并把它们插入或取出相应的 ADM 阶段。它是 adm 流程的中心。

#### 信息化总体架构方法

信息化是指通过通讯现代化、计算机化和行为合理化的总称
完整的信息化内涵包括：

- 信息网络体系
- 信息产业基础
- 社会运行环境
- 效用积累过程
  信息化建设指品牌利用现代信息技术来支撑品牌管理的手段和过程。
  信息化特征：
- 易用性
- 健壮性
- 平台化、灵活性、拓展性
- 安全性
- 门户化、整合性
- 移动性 （降低接入成本）

###### 信息化工程总体规划的方法论

- 关键成功因素法 Critical Success Factors CSF
  - 通过对关键成功因素的识别，找出实现目标所需的关键自信集合，从而确定系统开发优先次序。
  - 由组织确定关键成功因素。
  - 关键成功因素描述主要矛盾，使目标的识别突出重点。
- 战略目标集转化法 Strategy Set Transformation SST
  - 把组织的战略目标转变为管理信息系统的战略目标的过程
- 企业系统规划法 Business System Planning BSP
  - 通过自上而下地识别系统目标、企业过程和数据，然后对数据进行分析，自下而上地设计信息系统。
